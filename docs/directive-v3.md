## 1. Миссия

Фичевая стройка закончена — начинается жизнь продукта. Два контура работают постоянно и параллельно:

- **Контур A — Dogfooding:** команда реально живёт в RustTraycer. Разработка самого RustTraycer ведётся через RustTraycer.
- **Контур B — Parity-Watch:** живой Traycer не стоит на месте (1.1.6 → 1.1.10 за недели) — каждый его релиз отражается в parity-matrix и закрывается catch-up волной или ADR.

Выпуски: багфиксы = patch (v2.1.x), catch-up фичи = minor (v2.2, v2.3, …). Каждый релиз — через полный гейт и Release с ассетами.

---

## 2. Контур A — Dogfooding

**Определение.** Dogfood-сессия = реальная задача разработки этого репо (фикс, catch-up фича, рефакторинг), выполненная агентом **через продукт**: Task создан в RustTraycer, worktree — через `worktree.ensure` продукта, файлы правятся агентом через ladder, diff/commit — через git-панель или RPC, терминал — через PTY продукта. Работа мимо host'а dogfood-сессией не считается.

**Правила безопасности:**
1. Сессии — **только в worktree**, никогда в основном дереве. Merge в main — обычным гейтом (Reviewer + CI), как раньше.
2. Перед рискованными операциями (миграции storage, массовые правки) — бэкап durable-состояния через собственный `sync.push` на резервный архив. Ломаем продукт продуктом — восстанавливаемся продуктом.
3. Живые харнессы (`cli.claude`, `cli.codex`) поднимаются из env машины разработки (`RUSTTRAYCER_*_CMD`). Креды — только env/keyring, как всегда. Если живой харнесс недоступен — сессия на `cli.generic` с реальным скриптом, недоступность фиксируется в отчёте цикла.

**Учёт находок.** Всё, что найдено при реальном использовании, регистрируется в `docs/dogfood-log.md` с номером `DF-NNN`, категорией (bug / friction / idea) и severity:
- **P0** — падение host, потеря данных, порча репо: стоп-линия, hotfix немедленно, patch-релиз вне очереди.
- **P1** — фича не работает или ведёт себя не по спеке: закрывается в текущем цикле.
- **P2** — трение UX, неудобство, идея: триаж в бэклог, Chief решает волну.

Каждый DF-баг превращается в обычную задачу NNNN через гейт; в фиксе — регрессионный тест, воспроизводящий находку.

**Покрытие использованием.** За цикл реальное использование должны получить все зоны: ladder-режимы (ask и Yolo), запись файлов + commit, терминал + resume, artifacts, A2A-loop (с лимитами), sync push/pull, search/steer/stash. Матрица «эпик → последняя живая сессия» ведётся в dogfood-log.

**Цель самоприменения:** цикл 1 — ≥50% задач цикла через продукт; с цикла 3 — 100% там, где способность продукта это позволяет. Если способность не позволяет — это P1/P2 находка по определению.

## 3. Контур B — Parity-Watch

**Триггер:** новый тег `desktop-v*` в github.com/traycerai/traycer **или** обновление docs.traycer.ai/changelog. Architect проверяет источники в начале каждого цикла; пропуск релиза эталона — нарушение директивы.

**Процесс:**
1. Каждая новая способность эталона → новая строка `Cxx` в `docs/parity-matrix.md` со статусом `missing` + источник.
2. Триаж в том же цикле: либо строка попадает в catch-up волну (Chief планирует, minor-релиз), либо получает `out-of-scope-by-ADR` с обоснованием (существующие ADR-границы: телеметрия, managed cloud, CRDT, own inference, sharing/SSO — остаются законом).
3. **Инвариант матрицы: ни одна строка не живёт в `missing`/`partial` дольше одного цикла.**
4. Изменения протокола — только additive minor с handshake-совместимостью, как в v2.1 (1.0–1.9 живы).

---

## 4. Контур C — Гигиена

- `cargo audit` в CI — как есть; critical/high advisory = P0.
- Раз в цикл — dependency review: patch/minor бампы через обычный гейт, major — только ADR.
- Toolchain-канал обновляется только через ADR.
- Flaky-тест = P1: чинится или карантинится с задачей, зелёный CI не «перезапускаем до победы».

## 5. Цикл и его DoD

Цикл задаёшь сам (рекомендую 5–7 дней при текущем темпе), но не длиннее интервала релизов эталона. Цикл закрыт, когда:

- [ ] ≥10 dogfood-сессий, каждый доступный харнесс задействован, матрица покрытия обновлена;
- [ ] все P0 закрыты hotfix'ами, все P1 цикла закрыты, P2 оттриажированы;
- [ ] parity-matrix: 0 строк `missing`/`partial` старше цикла;
- [ ] CI зелёный, накопленное выпущено patch/minor релизом с ассетами;
- [ ] README и CHANGELOG соответствуют выпущенному (урок v2.1 — README-дрейф в чек-листе Reviewer).
